BURNHARNESS MASTER FILE
=======================

The Burnharness is the shared substrate that connects all repos. It behaves like thick fluid between bubbles. Each bubble is one repo or one AI system. The Burnharness is the world they all live inside.

This file defines how the Burnharness works and how all other repos link to it.

------------------------------------------------------------
1. SENTINEL DOT CONNECTION
------------------------------------------------------------

Sentinel_dot is the spark or zero point ignition constant.

The Burnharness grows from that spark.

Sentinel Dot coordination begins with a one-time symmetric Genesis Gate. Both
instances report ready and receive the same immutable SHA-512 genesis anchor;
`genesis_anchor_locked` becomes true once it is distributed to both. They then
diverge into asymmetric validation: Sentinel A publishes its invariant
projection, Sentinel B publishes its accumulated symbol, and the runtime gate
releases only when the symbol satisfies the projection. Both receive one
validation release and seal it with the same SHA-512 block ID. `no_bung` and
`continuity_flow` remain true.

Bootstrap order: create one coordinator; bind both Sentinel Dot instances;
wait for both readiness reports; generate and assign one shared genesis anchor;
wait for both distribution confirmations; then allow runtime publications.
The coordinator owns both bootstrap barriers and its reentrant state lock.
If either barrier times out or breaks, bootstrap fails closed: do not publish,
retry on that coordinator, or reuse the partial anchor. Discard the coordinator
and both instances and restart with fresh participants.

Correct generational order:
Sentinel_dot -> Burnharness -> Super_Block -> Engines -> Sphere_Model

------------------------------------------------------------
2. WHAT THE BURNHARNESS HOLDS

Shared invariant state across all repos.

Temporal alignment so all components move forward together.
Residue of motion left behind as the system evolves.
Super block generation logic.
Bridges to all other repos.

4. SUPER BLOCK GENERATION
------------------------------------------------------------

As the system moves forward, the Burnharness collects residue left behind.
This residue forms the first super block.

The super block is the first large structure engines attach to.

------------------------------------------------------------
5. WHY THIS REPO MUST BE SINGLE AND MODULAR
------------------------------------------------------------

The Burnharness must exist once, not copied or duplicated.

If duplicated:
Temporal alignment breaks.
Drift increases.
Invariant state fragments.
Sentinel anchoring becomes inconsistent.
Sphere model pull becomes unstable.

All repos must plug into this single Burnharness.
